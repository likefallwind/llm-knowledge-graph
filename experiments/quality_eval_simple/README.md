# 简化评测：内容准确，引用有据

2026-09-12。按用户要求，主问题只有两个，不合成总分，不预设方法胜负。

1. **抽取内容是否正确？** 正确 / 错误 / 无法确定。
2. **提交的引用是否足够支持该内容？** 充分 / 不充分 / 无法确定。

分别用于实体、核心关系、完整断言。实体检查名称所指、边界和已提供的真实定义；定义缺失不算幻觉，单列定义可用数量。核心关系检查参与者、关系方向、否定和必要条件；完整断言再检查描述中的全部实质内容。GraphRAG 等方法已保存的描述正常计入，不奖励谓词数量或长度。类型标签和别名不进入本轮主评分，不能通过原子拆分混入实体内容评分。

用同一批 160 个记录：每方法 20 实体、20 断言。每条断言分别评价核心关系和完整断言，合计 240 个简单判断；这是同一记录的两个视角，不是 240 个独立样本。

内容正确性的参考文本是原引用父段落加前后各一个相邻段落，所有方法同一规则。引用充分性只允许原提交的引用，不能借参考上下文补来源。参考上下文是局部文本，不是全书检索金标；因此证据不足时用无法确定，不能将不支持一律当错误。此轮仍不能据此评召回或全局身份归并。

允许合理改写、直接语义推论和作为限定的括号。“A 之前 B”按 A 先于 B 解释。先用 12 个受控开发例子检查正确与错误方向、括号、错引用、条件缺失、定义缺失和定义错误；预期答案冻结。该校准不是独立的裁判准确率证明。

移除原子事实拆分、具体性标签、逐段有效引用枚举和加权分数。引用长度/段落数仅作为辅助描述，始终按完整去重父段落计算；不把短且无据当作优势。不再要求模型输出复杂 JSON，采用两个枚举标签与一句理由，避免引号和公式引起格式失败。

四方法统一重评，不换样本、不覆盖旧结果；保留所有失败、不确定和分母。每类 20 个样本，结果属于同模型探索性试评，需要统一复核。缺失项不计入正确或错误，分别报告；确认正确数量除以固定样本数只是已确认比例。

官方 MiniMax-M3，**单进程、2 个工作线程、2 个 HTTP 请求槽位**，重试同样持有槽位。旧运行不重启。哈希冻结代码、传输、提示和任务。

准备：`python3 experiments/quality_eval_simple/evaluate.py prepare --run tmp/d2l-quality-simple-RUN`

运行冻结版本：`python3 tmp/d2l-quality-simple-RUN/evaluate.py run --run tmp/d2l-quality-simple-RUN`

产物：`progress.json`、`calibration-report.json`、`summary.json`、`review.json`、`REPORT.md`。后台日志 `run.log`，退出码 `.exit`，完整队列结束标记 `.finished`；退出 3 表示处理结束但仍有未评分项，不代表全部成功。
